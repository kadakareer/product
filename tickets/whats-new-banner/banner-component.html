Dismissible What's New banner

Per-event dismissible banner strip, capped at 3 on desktop / 1 on mobile, that stops surfacing an event once dismissed or past registrationCloseDate.

Technical solution

WhatWhere
Mount point App.jsx global, right under <NavBar/> — every page except /events, matching the design doc's "daily platform and website traffic" framing (showing it on the What's New page itself would be redundant, since that's the destination it drives to)
Fetch eligible events useApi({ url: '/api/v2/events/' }) src/pages/events/events.hooks.jsx reuse this fetch pattern in the banner's own hook; filter client-side to events where registrationCloseDate is in the future (mirrors isPastEvent in src/utils/events.ts) — depends on registrationCloseDate existing on the response
Per-event dismiss state getLocalStorage / setLocalStorage src/services/local-storage.js store an array of dismissed event IDs under one key, not the draft's single boolean flag
Desktop/mobile cap + overflow useIsMobile / useIsDesktop src/hooks/use-breakpoint.jsx
  • desktop: up to 2 individual event banners + a 3rd overflow banner ("N new events") linking to /events when more than 3 are eligible
  • mobile: 1 banner only
Copy truncation New util, colocated with the banner component desktop: 60 chars, one line, ellipsis; mobile: ≤30 chars one line, 31–60 wraps to two lines, beyond that truncates
CTA / dismiss controls
  • ButtonLink (src/components/atoms/buttons/index.jsx) for "Check it out"
  • dismiss "X": new plain styled button (no border/background) — no existing component to reuse for this
Analytics captureAnalyticsEvent src/services/analytics.js
  • 'Viewed Whats New Banner', 'Clicked Whats New Banner', 'Dismissed Whats New Banner' — each with { eventId, position }
tagging the registration-submit action with the originating banner wasn't scoped this pass — its capture call site wasn't located; needs a quick look before implementing that part
