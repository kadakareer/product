Handle a failed result email Backend · monorepo Admin · Retool

The status change and result email ticket saves the status first, then sends the email, and doesn't handle a failed send. If the send throws, the admin sees an error even though the status changed, and can't tell if the Kadet was emailed. This ticket catches the failure and tells the admin. Depends on that ticket.

Retool change: Event signups page. Questions: reach out to Ishi or Ken.

Technical solution

WhatWhere
Catch the send error The service method behind the admin status route functions/src/api/events/events.service.ts sendMail already turns SMTP and template errors into a MailError (mail/general, mail/template-nonexistent) and logs it. Catch that around the send. Never roll the status back, and log the error. functions/src/core/mail/mail.service.ts
Return the outcome Response of the admin status route add emailSent: true or false, and nothing when no email was attempted (toggle off, or a status that sends none). precedent: the VirApp batch decision endpoint already returns email_status SENT or FAILED per record. functions/src/api/challenges/challenges.service.ts
Tell the admin Save handler of the confirmation modal when emailSent is false, show "Status saved, email failed". The status stays changed.
