Email the Kadet on approve, reject or waitlist, and CC programs

CC programs@kadakareer.com so the program manager can confirm the Kadet's result email actually sent. Events send no such email today. The only event emails are a registration confirmation, sent when a Kadet registers in the app and not when the Tally webhook records one, and an event reminder. So this ticket adds the result emails and the CC together. Depends on the approve, reject or waitlist ticket, which is what triggers the send.

Technical solution

WhatWhere
Add one email template per result
  • approved
  • rejected
  • waitlisted
functions/src/core/mail/templates/ model on virapp-application-accepted.html and virapp-application-rejected.html. Wording comes from Programs.
Add the options type New interface next to IEventRegisteredOptions functions/src/core/mail/mail.interfaces.ts no cc field to add: the options already extend ISendMailOptions, which carries cc
Add the send method, with the CC New method next to sendEventRegistrationEmail, picking the template from the status functions/src/core/mail/mail.service.ts hardcode cc: 'programs@kadakareer.com'. Fixed address on every send, not per request, so no new API field.
Send it when admin sets the status The service method behind the new admin route functions/src/api/events/events.service.ts needs the Kadet's email and the event title and start time. create already fetches both with usersService.findOne and getEventById, so reuse that. Send only for approved, rejected and waitlisted, not for other status changes. save the status first, then send. A failed send never rolls the status back: catch the error, record it, and return emailSent: false in the response so the admin sees it.
Return the last email outcome in the admin list UserEventWithUserDto and getAllRegisteredUsersWithDetailsForEvent functions/src/api/events/dto/user-event-with-user.dto.ts add the latest email outcome per registration (sent, sent time, error), read from the newest status-history row, so the table can show "Approved — email failed"
Let admin resend New admin route next to the status route, with the same guards (Admin and Program Manager) functions/src/api/events/events.controller.ts resend sends the email for the registration's current status. Only on request, never automatic retry, so a Kadet can't get two. Each resend updates the same history row.

Decided: a failed email is recorded, never rolled back, because the status change is the source of truth and mail here is plain SMTP with no fallback. The outcome is stored on the status-history row (see that ticket).
