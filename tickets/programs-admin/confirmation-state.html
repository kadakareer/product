Record whether an approved Kadet confirmed their seat Backend · monorepo

After approval, the Kadet confirms or declines their spot. It's stored next to the status, not inside it: the status stays APPROVED, and a new field says awaiting, confirmed or declined. A declined seat is no longer held, so the waitlist can use it later.

Depends on the status change ticket, which adds the admin status route.

Technical solution

WhatWhere
Add the confirmation field New enum UserEventConfirmation (AWAITING, CONFIRMED, DECLINED) and an optional confirmation field on UserEvent functions/src/api/events/entities/user-event.entity.ts registrations approved before this ships have no value. Treat "no value" as "nobody asked", not as awaiting, so old events don't flood the Awaiting count. No backfill.
Set it to awaiting on approval The service method behind the admin status route functions/src/api/events/events.service.ts when the status becomes APPROVED, set confirmation to AWAITING. When the status moves anywhere else, clear it.
Add a route for the Kadet to answer PATCH /users/:uid/events/:eventId/confirmation, next to the existing routes. Already guarded to the owner. functions/src/api/users/users-events.controller.ts new DTO accepting only CONFIRMED or DECLINED. Don't reuse UpdateRegistrationDto: it deliberately can't change status, and this must not either.
Enforce the rules New service method behind that route functions/src/api/events/events.service.ts
  • Only when the status is APPROVED and the confirmation is AWAITING, otherwise reject
  • Once answered, it's final for the Kadet. A declined seat may already be given away, and a Kadet whose plans change can email the team. Only an admin can change it
Let the admin set it too Admin route next to the admin status route, same guards: Admin and Program Manager functions/src/api/events/events.controller.ts for a Kadet who answered by email or can't use the page. Role-only, no EDIT_SIGNUPS. Calls the same service method without the Kadet-only rules.
Return it Nothing to add. The registrations list and the Kadet's own registration lookup both return the whole UserEvent, so the new field comes through. add confirmation to UserEventWithUserDto so the API contract lists it. functions/src/api/events/dto/user-event-with-user.dto.ts
Link the approval email to the event page The approved template from the status ticket functions/src/core/mail/templates/ add a "Confirm your spot" button to https://app.kadakareer.com/events/{{eventId}} and pass eventId in the options. Templates already hardcode app.kadakareer.com.

Not in this ticket: freeing the seat for the waitlist. Events have no capacity yet. This ticket only records DECLINED, so the capacity ticket can stop counting it and offer "Fill open spot" to the admin.

Let the Kadet confirm or decline from the event page Frontend · app-playground

The email links to the event page. When the Kadet has a spot to confirm, the button area shows Confirm my spot and Can't make it. No new page and no new route in the app.

Depends on the backend card above.

Show and set the confirmation in the registrations table Admin · Retool

Approved rows get a Confirmation column the admin can read and change. A filter narrows the table by confirmation, and two summary tiles show the counts.

Prototype: Program sign-ups. Retool change: Event signups page. Questions: reach out to Ishi or Ken.

Depends on the backend card above.

Technical solution

WhatWhere
Add a Confirmation column Registrations table awaiting, confirmed or declined for approved rows, "—" for everything else, including old approved rows with no value.
Let the admin change it A dropdown in that cell, saving through the new admin route show the new value only after the save succeeds. On failure keep the old value and show an error.
Add a confirmation filter A second filter next to the status filter: all, awaiting, confirmed, declined
Add Confirmed and Awaiting confirmation tiles Two tiles after Approved in the tile row from the summary tiles ticket. Hidden at zero Awaiting counts approved registrations that are neither confirmed nor declined. Declined registrations appear in neither tile. The prototype calls the field commitment. clicking a tile sets the status filter to Approved and the confirmation filter to that state. wait for the design review before building the tiles. The column, dropdown and filter don't wait.
