Technical solution

WhatWhere
Count registrations by status The registrations query the table already uses GET /events/:eventId/registrations load the list without a status filter and count it in a transformer. No new endpoint. If the list is ever paginated, the counts must come from the server instead.
Add the tile row above the table Three tiles, left to right
  • Pending review: APPLIED. Hidden at zero
  • Waitlisted: WAITLISTED. Hidden at zero
  • Approved: APPROVED. Always shown
the prototype also counts COMPLETED in Approved, because a completed registration still holds a seat. Confirm whether to keep that.
Click a tile to filter the table Set the table's existing status filter to the tile's status keep the status dropdown in sync with the tile. Make the tiles reachable by keyboard: Enter and Space filter like a click.
Recount after a status change Save handler of the status dropdown update the tiles only after the save succeeds, the same rule as the row's status.
