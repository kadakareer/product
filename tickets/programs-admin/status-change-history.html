Track status changes per registration

Admin wants an audit trail of when a registration's status changed and what changed it. Nothing is tracked today: a status change overwrites the previous one, and cancelling a registration deletes the record outright, history included. Status can change through four separate service methods, with no single place to hook a log.

Technical solution

WhatWhere
New history entity, one doc per status change New flat top-level collection user_event_status_history same flat-collection pattern as user_event itself (fireorm, no subcollections in use)
  • userId and eventId — stored directly, not just a link to the registration, because cancelling deletes that doc
  • previousStatus / newStatus — previousStatus null on first create
  • changedBy — user id, or a fixed marker for the Tally webhook
  • source — which path made the change (see below)
  • changedAt
  • emailSent — null when the change sends no email, otherwise true or false
  • emailSentAt — nullable
  • emailError — short message when the send failed
Route every status change through one function that writes the row functions/src/api/events/events.service.ts
  • create — caller sets the status in the request body
  • upsertFormRegistration — Tally webhook, writes APPLIED or APPROVED
  • update — can't change status today; the new admin route from the status ticket would
  • delete — write a final row before removing the record
write the row in the same call as the status change, so a change can't land without its history. Then send the email and update that same row with the outcome. Two writes, so the audit entry survives if the process dies between the change and the send. A resend updates the same row, so it shows the first failure and the later success.
Record the old status before it's overwritten updateRegistration and upsertRegistration functions/src/api/events/event.repository.ts upsertRegistration already reads the existing record to refuse overwriting protected statuses, so the previous status is available there
Return the last email outcome in the admin list UserEventWithUserDto and getAllRegisteredUsersWithDetailsForEvent functions/src/api/events/dto/user-event-with-user.dto.ts add the latest email outcome per registration (sent, sent time, error), read from the newest status-history row, so the table can show "Approved — email failed"
Let admin resend New admin route next to the status route, with the same guards (Admin and Program Manager) functions/src/api/events/events.controller.ts resend sends the email for the registration's current status. Only on request, never automatic retry, so a Kadet can't get two. Each resend updates the same history row.

Depends on the status ticket, which adds the admin status route and the result emails. That ticket only returns emailSent: false on the save response. This ticket records the outcome, shows it in the list, and adds resend.

Decided: a failed email is recorded, never rolled back, because the status change is the source of truth and mail here is plain SMTP with no fallback.
