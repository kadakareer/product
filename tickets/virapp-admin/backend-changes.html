Track status changes and email sends per applicant

Admin wants an audit trail of when an applicant's status changed (and by whom), plus whether the accept/reject email actually sent — currently neither is tracked, and email-sending itself is inconsistent across the three call sites that can change status.

Technical solution

WhatWhere
New history entity, one doc per status change New flat top-level collection user_challenge_status_history codebase has no subcollection convention (fireorm, no @SubCollection in use anywhere) — mirror the existing flat-collection pattern instead of inventing one
  • userChallengeGroupId — FK to the UserChallengeGroup doc
  • previousStatus / newStatus
  • changedBy — admin id
  • changedAt
  • emailRequested — bool, did the caller ask for an email
  • emailSent — bool, did it actually go out
  • emailSentAt — nullable
Consolidate status-change + email logic into one path functions/src/api/users/users-challenges-new.service.ts
  • updateEnrollmentStatus — has send calls commented out/dead
  • batchUpdateEnrollmentStatus — never sends
  • batchUpdateEnrollmentStatusForPairs — sends only if sendEmail: true
route all three through one function that updates status, sends the email when requested, then writes a single history row with the actual email outcome — so the row is written once, self-contained, not split across two writes
Wire up the send call in the currently-dead path mailService.sendVirappApplicationResultEmail functions/src/core/mail/mail.service.ts needs applicantName (from usersService.findOne) and virappChallengeName (from cmsService.getChallengeDashboard) — both extra fetches not otherwise available inside updateEnrollmentStatus today
