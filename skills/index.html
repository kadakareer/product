PM skills

Read this first: the one risk that applies to everything

  • Prompt injection. Any skill that reads text someone else wrote (a repo, a pull request, an issue, a web page) can be steered by instructions hidden in that text.
  • A markdown-only skill has no code to run, but it is still exposed through what it reads.
  • Safest habit: keep Claude's permission prompts on, and don't point a skill at an untrusted repo or pull request while it can write, push or publish.

Before you install anything
#CheckWhat to look for
1Where is it from?Owner, age, last push. A new, small, single-author repo gets read line by line.
2Does it run code?scripts/, hooks/, settings.json, and install steps like npx or curl.
3Read the SKILL.mdMost are 1 to 12 KB. That is minutes, not hours.
4What does it read?Repo files, pull requests, issues and web pages are all places injected instructions can hide.
5What can it change?Writing files, git actions, publishing to a tracker. Prefer skills that only produce text for you to review.
6Does the license fit?Dean Peters' pack is non-commercial share-alike. Ask before using it for org work you redistribute.
7Copy the folder, don't plugin-installA plugin can follow the upstream repo, so later edits change what you run. A copied folder stays as you reviewed it.
Try one safely
  • Use a scratch repo with no secrets and no push access.
  • Copy one skill folder into that repo's .claude/skills/. For grill-me, also copy grilling, since it calls it.
  • Run it on one real task from your week. Keep it only if it earned its place.
Not checked
  • I did not run any skill or script.
  • I read most listed SKILL.md files only partly, and not the bundled scripts in full. A simple search of code-to-prd's two scripts found no network or subprocess calls, which is not a code review.
  • Install commands come from READMEs and are untested.
  • Repos change. Recheck last push and contents before relying on any of this.
